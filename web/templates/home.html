How one fix is made

  1. DetectPlain code watches the simulated provider and ledger and opens an incident. No model is involved.
  2. InvestigateThe agent reads the provider and ledger with read-only tools. Free text from customers is fenced off and never used as evidence.
  3. Pass the gateEvery write goes through a policy gate written in code: spending caps, an idempotency key, evidence that really exists, and a check specific to the incident type. The model's own words never reach it.
  4. ActThe intent is committed to the chain before the action runs, so nothing happens that the record does not show.
  5. VerifySeparate code re-reads the provider and ledger. Only it can close an incident. The model saying "done" counts for nothing.
  6. RecordEach step is a hash-linked entry, and every incident gets a receipt anyone can re-check against the chain.
